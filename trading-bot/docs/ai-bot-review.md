# AI trading bot review — 22 October 2026

The rebuild was compared with these primary sources. The additions below are in a separate commit from the requested stock-only rebuild. They are locally written implementations of architectural ideas; no third-party source was copied and no new runtime dependency was added.

| Project and inspected source | Useful method | Local adoption |
| --- | --- | --- |
| [Freqtrade/FreqAI](https://github.com/freqtrade/freqtrade/blob/c051e9065c5b677f03817dd1f83cb980af1ed684/freqtrade/freqai/freqai_interface.py), `build_strategy_return_arrays`; [model-expiry documentation](https://www.freqtrade.io/en/stable/freqai-running/#defining-model-expirations) | An expired model has an explicit status per instrument, separate from its numerical predictions. | `app/prediction_quality.py` checks model identity, settings, timezone-aware training timestamps, training age and input age for each stock. `MODEL_MAX_AGE_HOURS=168` is configurable (12–720). Daily decisions and chart forecasts abstain when quality is unavailable. Intraday models abstain from their veto while a fresh independent playbook may still enter. Existing price stops and pre-close exits remain independent of model availability. |
| [TradingAgents dated data](https://github.com/TauricResearch/TradingAgents/blob/e8f5503e9b86d5c2710b0c76b1f686703968c9df/tradingagents/dataflows/date_window.py) and [run settings/report notes](https://github.com/TauricResearch/TradingAgents/blob/e8f5503e9b86d5c2710b0c76b1f686703968c9df/README.md) | Data must belong to the decision's time window, and a report should retain its inputs/settings. | A research run fixes its `as_of` instant. News requests include that end time; future, stale, undated and duplicate articles cannot enter evidence. Each stock and the market overview retain source evidence hashes, requested/returned model IDs, prompt version, horizon and input-bar timestamp in SQLite. No credentials are included. |
| [TradingAgents structured output helper](https://github.com/TauricResearch/TradingAgents/blob/e8f5503e9b86d5c2710b0c76b1f686703968c9df/tradingagents/agents/structured.py) | Decision outputs should have a defined schema and explicit missing-evidence behavior. | The rebuild keeps a small local validator: exactly one answer for the requested stock, finite confidence, an allowed action, nonempty rationale and citations restricted to supplied source IDs. Malformed responses abstain. There is no free-text trading fallback and no extra LLM call to repair a response. |

The FreqAI reference is used only for stock-model lifecycle ideas. Its exchange integrations and asset support are not imported. TradingAgents' multi-agent debate pipeline is not added: it would increase request counts and conflict with the requested single stock request/vote. Historical prediction replay, chronological train/holdout separation and order reconciliation already existed in this repository and remain in place.

These are operational correctness improvements. They do not establish a profitable edge. Rankings still select from past backtests; forward paper results are required to assess actual behavior. No broker orders or live model calls were made during this review.

Validation covers independent model expiry, bad/future/naive timestamps, playbook behavior without fresh models, evidence hashes, strict news time windows, per-stock request isolation, candle session boundaries and the original regression suite.
